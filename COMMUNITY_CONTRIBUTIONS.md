# Участие сообщества

Владелец включает и отключает предложения на отдельной странице из редактора приложения.
Требуется пароль и действующий TOTP-код, если включена 2FA. Для аккаунта без локального
пароля сначала нужно установить пароль. Включение доступно для публичных приложений без DMCA.

Разработчики предлагают изменения информации, создание и изменение дистрибуций через
существующие заявки. Предложения всегда рассматривает модератор, даже от доверенных авторов.
Одновременно допускается одна заявка на изменение приложения или конкретной дистрибуции;
для новых дистрибуций — одна ожидающая заявка от автора на приложение. Устаревшие предложения
и предложения для приложений с отключённым доступом сообщества не применяются.

Владелец сохраняет управление. Предложения не меняют владельца, настройки доступа, отзывов
или значки. После первого включения приложение нельзя удалить или сделать приватным через
редактор владельца. Отключение предложений не отменяет защиту. При удалении владельца
приложение и дистрибуции сохраняются; автор отображается как «Сообщество». Администраторы
сохраняют возможность применять DMCA и ограничения видимости.

## Развёртывание

1. Применить миграции `0051` и `0052` стандартным `python manage.py migrate`.
2. Обновить все Django-сервисы и workers перед использованием новых действий.
3. Выполнить обычную сборку Babel и collectstatic.

Миграция `0051` добавляет поле с постоянным DB default и снимает NOT NULL с владельца,
сохраняя существующий FK. Она требует краткой блокировки ACCESS EXCLUSIVE;
`SET LOCAL lock_timeout = '2s'` прерывает ожидание занятой таблицы. В этом случае повторите
миграцию после завершения мешающей транзакции. `0052` отдельной транзакцией защищает
приложения, для которых участие сообщества уже было включено в PR №83.

Обратная миграция намеренно не возвращает NOT NULL: сохранённые приложения могут уже
не иметь владельца. После появления таких приложений откат на прежний код требует
отдельного плана восстановления владельцев; прежний код не поддерживает пустого автора.

Миграции выполняются один раз для каждой базы. Django записывает их применение в
`django_migrations`; последующие вызовы `migrate` пропускают уже выполненные миграции.
Включение режима и удаление владельца меняют обычные записи и не запускают миграции.
Рабочие операции блокируют конкретные строки, а не всю БД. Чтение страниц и проверки
CDN не удерживают блокировки приложений. Массовое удаление блокирует выбранных пользователей.
Таймаут 2 секунды ограничивает ожидание блокировки, а не длительность всей миграции.

При обновлении нужно заново получить токен для ещё не подтверждённых приватных загрузок:
старые токены не имеют привязки к приложению в серверном кеше. Сам формат подтверждений
LunaSpire не меняется; привязка проверяется по одноразовому guard, который выдаёт API.
