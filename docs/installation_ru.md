# <center>Инструкция по установке LunaStore</center>

В первую очередь, стоит убедиться, что ваш сервер для установки соблюдает следующие требования:

* **Процессор**: 2 и более ядра
* **ОЗУ**: 2 и более GB оперативной памяти
* **Память**: 10 и более GB диска
* **..а также наличие установленного Docker'а, Docker Compose, Python 3.12+, PostgreSQL 17+, PIP, OpenID (Authentik like) сервиса, нашего движка LunaSpire**

Кстати говоря, с недавнего времени у нас появился автоматический установщик LunaStore (находится в корне проекта; setup.sh / setup.ps1, зависит уже от того, на какой вы системе)

Использовать ручную или автоматическую установку - решать сугубо вам.

### 1. Скачивание исходников

Для начала, стоит склонировать исходники LunaStore:

```bash
git clone https://git.myslivets.com/myslivets/lunastore
```

### 2. Установка библиотек

После того, как вы скачали исходники, необходимо скачать нужные библиотеки:

```bash
pip install -r requirements.txt
```

### 3. Настройка конфигурации

Затем, уже после установки, откройте в любом удобном для вас текстовом редакторе .env.example и настройте его:

#### Основная конфигурация и конфигуация OpenID

| Переменная | Описание | По умолчанию
| ------ | ----------- | ----
| SITE_URL  | URL вашего сайта; оставьте пустым, если не знаете, что делаете | `""` (None) | |
| OIDC_CLIENT_ID | Client ID вашего OpenID (Authentik like) сервиса; | |
| OIDC_CLIENT_SECRET   | Client Secret Key вашего OpenID сервиса; | |
| OIDC_ENDPOINT | Endpoint для OpenID сервиса | |
| OIDC_TOKEN_ENDPOINT | Endpoint для токена | |
| OIDC_USER_ENDPOINT | Endpoint для получения информации о пользователе в OpenID сервисе | |
| LOGIN_REDIRECT_URL | URL, на который пользователя будет переводить при входе на аккаунт через ваш OpenID сервис (обычно, стоит кидать пользователя на саму админ-панель LunaStore; к примеру: `http://localhost:8088/admin`) | |
| LOGOUT_REDIRECT_URL | То же самое, что и LOGIN_REDIRECT_URL, но тут URL уже при выходе из аккаунта | |
| OIDC_SIGN_ALGO | Алгоритм подписи для OpenID, но обычно стоит указывать `RS256` (зависит уже от вашего OpenID сервиса) | `RS256` |
| OIDC_JWKS_ENDPOINT | URL на ваш JWKS в вашем OpenID сервисе  | |

> **Уточнение**: Обычно, параметры которые касаются OpenID можно не трогать, ибо используется OpenID в LunaStore в качестве доп. метода для входа в админ-аккаунт. При этом, админ-панель может спокойно работать и без OpenID, как и весь сайт.

#### Настройка БД (PostgreSQL)

| Переменная | Описание | По умолчанию
| ------ | ----------- | -----
| DB_NAME  | Название вашей базы данных (к примеру, lunastoredb) | `lunastoredb` |
| DB_USER | Имя аккаунта от вашей базы данных (к примеру, postgres) | `postgres` |
| DB_PASSWORD   | Пароль от вашей базы данных | |
| DB_HOST | IP/домен вашей базы данных (заранее убедитесь, что по этому IP/домену можно подключиться к вашей базе данных) | `127.0.0.1` |
| DB_PORT | Порт, на котором работает база данных | `5432` |

#### Внутренняя настройка LunaStore

| Переменная | Описание | По умолчанию
| ------ | ----------- | -----
| EXTERNAL_MEDIA_URL  | Прямая HTTP-ссылка до папки с внутренним UGC контентом (во многом, указывать ее не обязательно, но все же, лишней не будет) | `http://192.168.1.10/media/` |
| SECRET_KEY | Секретный ключ от самого Django (т.е. сайта); разумеется, данный ключ лучше не стоит показывать кому-либо | mysuperkey123 |
| DEBUG   | Режим отладки проекта (грубо говоря, при работающем DEBUG у вас будет выводится куча логов для непосредственно отладки проекта), но для продакшена советуем поставить True | False |
| LUNASPIRE_SECRET_KEY | Секретный ключ от нашего движка LunaSpire; он должен совпадать с тем, что вы указали в .env самого LunaSpire | supersecretkey |
| LUNASPIRE_URL | Прямой URL до инстанса LunaSpire | `http://192.168.1.10:8080` |
| API_URL | Прямой URL до LunaStore API | `http://192.168.1.10:7088` |
| ALLOWED_HOSTS | Перечисление IP/адресов (без http/https), с которых можно будет зайти на LunaStore. ; в данной переменной является разделителем между несколькими IP/доменами | `192.168.1.10;192.168.1.1` |
| CORS_ALLOWED_ORIGINS | Разрешенные IP/домены для CORS. Разделитель здесь такой же, как и в ALLOWED_HOSTS | `http://192.168.1.10;http://192.168.1.1` |
| MOTD_LIST | MOTD вашего инстанса LunaStore; Их может быть несколько, а показываться они будут рандомно. Разделитель здесь такой же. | `Windows XP;время подавать напитки и вершить судьбы` |
| BCRYPT_ROUNDS | Указывает на то, сколько раз будет выполнен процесс хэширования со стороны bcrypt; Обычно, лучше оставлять стандартное значение | 12 |
| REGISTRATION_IS_ENABLED | Указывает на то, включена ли регистрация в LunaStore | `True`
| DEVELOPER_REGISTRATION_IS_ENABLED | Указывает на то, нужно ли получить статус разработчика прежде чем заливать приложение в LunaStore | `True` |
| RETENTION_ACTIVITY_LOG_DAYS | Указывает на то, сколько хранятся данные из User Activity Log (включая IP пользователей) на основе политики GDPR | 0 |
| INVITES_ON_REGISTER | Указывает на то, доступна ли регистрация только по инвайт-коду | `True` |
| MAX_INVITE_USES_COUNT | Указывает на то, сколько раз можно пригласить пользователей за 1 инвайт-код | 3 |
| MAX_INVITE_DAYS_LIMIT | Указывает на то, сколько раз можно пригласить пользователей за день | 7 |

А теперь, переименуйте .env.example в .env:

```bash
mv .env.example .env
```

### 4. Применение миграций к БД

После чего, необходимо будет применить миграции к вашей базе данных для корректной работы LunaStore:

```bash
make migrate
```
..или `make dev-migrate`, зависит все это от того, хотите ли вы поднять production или development версию LunaStore

А затем:

```bash
make cachetable
```
..или `make dev-cachetable`

### 5. Создание root пользователя

Для того, чтобы вы могли без проблем зайти в админ-панель, необходимо создать аккаунт администратора:

```bash
make superuser
```
..или `make dev-superuser`

### 6. Сборка LunaStore

И финал - билд исходников и запуск инстанса! Чтобы сбилдить и запустить свой LunaStore, напишите следующее:

```bash
make build
```
..или `make dev-build`

А затем, после билда проекта, напишите следующее:

```bash
make up
```
..или `make dev-up`

## ℹ️ Дополнительная информация

LunaStore состоит из 2-ух контейнеров:

1. **lunaStore**: держит основной функционал и страницы сайта (работает на порте **9088**)
2. **lunaStoreAdmin**: держит функционал админ-панели и прочих вещей, которые необходимы для адекватной работы админ-панели (работает на порте **8088**)
3. **lunaStoreAPI**: держит функционал API (работает на порте **7088**)

* **Доступ к админ-панели**: чтобы попасть туда, зайдите на `http://ваш-ip:8088/admin`
* **Изменение портов**: если вы захотите поменять порты - вам нужно будет их менять в файле `docker-compose.yml` или `docker-compose.dev.yml` (зависит от того, какую версию LunaStore вы поднимали)
